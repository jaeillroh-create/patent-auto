# DIAG — 도면 번호 체계 일관성 (라벨·SVG제목·식별번호·발명설명)

> 브랜치: `review-engine/diag-figure-numbering` · READ-ONLY 진단(코드 0)
> 결론 한 줄: 도면 번호는 **단일 함수(`computeFigNums`)로 계산은 되지만**, ① **예시도 SVG 제목 【도 N】만 LLM이 따로 써넣고 코드 동기화가 없어** 계산값(라벨·발명설명)과 어긋나고(장치도면 mermaid는 코드가 제목을 박아 안 어긋남 — 대조), ② **식별번호(31~99)가 도면번호가 아니라 "유형"에 묶여 있어**(ui_screen 31~50…) 도N→N0번대 관행이 없으며, ③ **예시도의 도 번호·순서를 사용자가 지정할 수 없다**(순서 device→concept→method 고정, 사용자 지정은 업로드 이미지 한정). → ★ **도면번호를 단일 진실원(SoT)으로 세우고 SVG제목·식별번호·발명설명이 거기서 파생되게** 만드는 게 근본.

---

## 1. 도면 번호 계산 현황 — 계산은 1곳, 소비는 4곳(SVG 제목만 이탈)

### 1-1. 계산 — `computeFigNums(devCount, methCount, conceptCount)` (3293)
```
순서: 장치(1..) → ★예시도 → 방법   (예시도는 장치 뒤·방법 앞)
requiredFigures(사용자 업로드).num 은 건너뜀(스킵)
반환: { device:[..], concept:[..], method:[..] }
```
- `getAutoFigNums(sid)`(3305): `diagramData.step_07.length`(장치 수)·`step_11.length`(방법)·`conceptDiagramTypes.filter(svgContent).length`(예시도) 로 매번 **동적 재계산** → sid의 슬라이스 반환.

### 1-2. 소비 4곳 — 번호 출처 비교
| 소비처 | 번호 출처 | 동적/고정 | 일관성 |
|--------|-----------|-----------|--------|
| **라벨**(카드 "도 N") `renderConceptDiagramCards` | `getAutoFigNums('step_07c')` | 동적(렌더 시점) | 기준 |
| **마커/간단설명** `outputs.step_07c` | 생성 시 `figNums=getAutoFigNums(...)` → 텍스트에 baked | 생성 시점 고정 | 라벨과 보통 일치 |
| ★ **SVG 제목 【도 N】** (도면 안) | ★ **LLM이 작성**(프롬프트 5616 "제목: 【도 N】 표기") | ★ **LLM 재량·미동기화** | ★ **이탈(① 불일치)** |
| **발명의 설명**(step_08) | `_conceptFigNums[indexOf]`=`getAutoFigNums` | 생성 시점(동적) | 라벨과 일치(둘 다 계산) |

> ★ **대조 — 장치도면(mermaid)**: SVG 제목을 **코드가 박는다** — `svg+='【도 '+figNum+'】'`(8082)·PPTX `'【도 '+fn+'】'`(8096). 그래서 mermaid는 제목이 figNum과 **항상 일치**. **예시도(SVG-direct)만 LLM이 제목을 써서** figNum과 어긋날 수 있다.

### 1-3. ① "라벨 도5 vs SVG제목 도4" 의 메커니즘
- (a) **LLM 오기**: 프롬프트가 `figNums[i]`(예 5)를 주지만 SVG 제목 텍스트는 자유서술 → LLM이 【도 4】로 잘못 적음. **코드가 교정/동기화하지 않음.**
- (b) **stale baking**: 생성 당시 장치 수=3 → 예시도=도4로 baked. 이후 장치도면이 1개 늘어 장치 수=4 → 라벨=`getAutoFigNums`=도5로 이동. **SVG 제목은 baked 【도 4】 그대로** → 어긋남.
- ★ 공통 근본: **예시도 SVG 제목이 코드 동기화 없이 LLM 산출물로 고정** → 계산값(라벨/설명)과 분리.

## 2. 식별번호 ↔ 도면번호 (② 불일치 — 도N→N0번대 없음)

```
CONCEPT_DIAGRAM_TYPES refRange (80~84):  ui_screen 31~50 / user_scenario 51~60 /
                                          data_structure 61~70 / device_appearance 71~80 / process_scene 81~99
프롬프트(5616 등): "참조번호 31~99"(평면) · 추출(_parseConceptRefMap): 31~99 평면 필터
```
- ★ 식별번호 범위는 **"유형"에 묶여 있다**(UI=31~50…). **도면 번호와 무관.** 그래서 **도 5(UI 화면)도 31~ 식별번호**를 쓴다(50번대 아님).
- ★ 관행(**도N → N0번대**: 도3=31~39, 도5=51~59)은 **미구현**. 현재는 유형 기반(또는 31~99 평면)이라 도면번호와 연동 안 됨.
- ⚠️ refRange(유형별)와 프롬프트/추출(31~99 평면)도 **서로 불일치**(유형 범위는 사실상 사문화, 생성은 평면 31~99).

## 3. 도면 순서 (③ 사용자 지정 불가)

- **순서 고정**: `computeFigNums` 가 장치 → 예시도 → 방법 순으로 **자동 배정**. 예시도는 항상 장치 뒤. **사용자가 예시도를 도 3(중간)에 끼울 수 없다.**
- **사용자 지정은 업로드 이미지 한정**: `requiredFigures`(사용자 업로드 도면)는 `inpRequiredFigNum`(2004, min1 max30)으로 **번호 지정 가능**하고 `computeFigNums` 가 그 번호를 **스킵**해 비켜준다. 그러나 **자동 예시도(step_07c)에는 그런 번호 지정 필드·로직이 없다.**
- ★ 즉 "예시도를 도 3에 배치 + 나머지 자동 도면이 밀림"은 **현재 불가**(예시도용 순서/번호 지정 UI 부재).

## 4. 발명의 설명(step_08) 연동

- step_08 프롬프트는 예시도를 `도 ${getAutoFigNums(...)}: [유형] (참조번호: 이름(번호)…)` 로 주입(4281) → "도 N을 참조하면,"으로 기술. **figNum·식별번호 모두 동적(getAutoFigNums)·refMap 기반.**
- 의존성 `step_07c MUST step_08·step_18`(2238) → 예시도 바뀌면 step_08·step_18 **무효화→재생성** 시 따라옴.
- ★ **단, 두 약점**: (a) step_08의 figNum은 따라오나 **SVG 제목(baked)은 안 따라옴**(①) → 본문 "도 5" vs 도면 제목 "도 4" 괴리. (b) 순서를 바꿔도(③ 불가지만 가정) step_08은 `getAutoFigNums` 로 따라오나 **SVG 제목·식별번호 체계는 안 따라옴**.

## 5. 근본 진단 — "단일 체계 없음"의 실체

| 항목 | 단일 진실원? | 현실 |
|------|-------------|------|
| 도면 번호 계산 | ✅ `computeFigNums` 1곳 | 그러나 **동적 재계산**(장치 수 변동 시 예시도 번호 이동) |
| SVG 제목 【도 N】 | ❌ | **LLM이 별도 작성, 코드 미동기화** → ① 이탈 (mermaid는 코드가 박아 안 이탈) |
| 식별번호 | ❌ | **유형 기반(31~99), 도면번호 무관** → ② 도N→N0 없음 |
| 도면 순서 | ❌(사용자) | **device→concept→method 고정**, 예시도 사용자 지정 없음 → ③ |
| 발명의 설명 | △ | figNum·refMap은 동적 추종, 그러나 SVG제목·식별번호 체계와 분리 |

★ 요지: **번호 "계산"은 단일이나, 그 계산값을 SVG제목·식별번호가 따르지 않고 각자(LLM 작성·유형 고정) 논다.** 그래서 같은 도면을 두고 라벨/제목/식별번호가 어긋난다.

## 6. 개선 방향 (도면번호 = 단일 SoT, 나머지가 파생)

| 항목 | 방향 | 트레이드오프 |
|------|------|--------------|
| ★ ① SVG 제목 동기화 | 파싱/렌더 시 **코드가 예시도 SVG의 제목을 figNum으로 강제**(mermaid 8082 방식 이식): LLM이 쓴 【도 X】를 제거하고 코드가 【도 figNum】을 오버레이. → 라벨·설명과 항상 일치 | 저위험·확실. LLM 제목 신뢰 제거 |
| ★ ② 식별번호 figNum 연동 | **도N → N0번대**로 식별번호 범위를 figNum에서 파생(도3→31~39, 도5→51~59). 프롬프트·추출·부호의 설명·step_08 일괄 정렬. 유형 refRange(사문화)는 폐기 | 중간. 두 자리(도1~9까지 11~99) 가정 — 도10+ 예시도는 드묾(정책 필요) |
| ★ ③ 사용자 순서 지정 | 예시도에 **도 번호/위치 지정 필드**(requiredFigures.num 패턴 차용) + `computeFigNums` 가 지정 위치 존중(나머지 자동 도면이 밀림). 예시도 카드에 순서 UI | 중간. 충돌·범위 검증 필요 |
| ④ 발명설명·부호 추종 | ①②③ 후 step_08/부호의 설명이 **단일 figNum·식별번호 체계**를 따르도록(이미 getAutoFigNums·refMap 동적이라 대부분 자동). SVG제목 동기화(①)로 본문↔도면 일치 | 저위험(대부분 기존 동적 추종 재사용) |

**권장 순서**: ① SVG 제목 동기화(가장 명백·저위험·체감 큼) → ③ 사용자 순서 지정(번호 SoT 확정) → ② 식별번호 figNum 연동(SoT 위에서 파생) → ④ 설명·부호 추종 검증.

## 7. 핵심 질문 — 직답
- **라벨 vs SVG제목 번호 왜 다른가** → 라벨은 `computeFigNums`(코드 계산), **SVG 제목은 LLM이 따로 작성·코드 미동기화**. LLM 오기 또는 장치 수 변동 후 stale baking → 어긋남. (mermaid는 코드가 제목을 박아 안 어긋남.)
- **식별번호가 도면번호와 연동되나** → **아니다.** 식별번호는 **유형 기반(31~99)**, 도면번호 무관. 도N→N0번대 미구현.
- **도면 순서 사용자 지정 가능한가** → **예시도는 불가**(순서 device→concept→method 고정). 사용자 지정은 **업로드 이미지(requiredFigures)** 에만(번호 max 30).
- **발명의 설명이 도면 번호·순서 따라가나** → figNum·식별번호는 `getAutoFigNums`·refMap 으로 **동적 추종**(재생성 시). 단 **SVG 제목(baked)은 안 따라와** 본문↔도면 괴리.
- **★ 도면 번호 체계가 단일·일관한가** → **계산은 단일(`computeFigNums`)이나 일관하지 않다** — SVG제목(LLM)·식별번호(유형)·순서(고정)가 그 계산을 따르지 않는다. 단일 SoT로 세우고 파생시키는 정비 필요.
