# DIAG — 예시도(개념도) 설명이 명세서 본문(발명의 설명·부호의 설명)에 누락

> 브랜치: `review-engine/diag-concept-spec-missing` · 기준: `origin/main`(③ PR #209 **미병합** 상태) · 코드 변경 0
> 증상: 장치도(도 1~3)는 도면 + 발명의 설명 + 부호의 설명 정상. **예시도(도 4·5)는 도면은 그려지나 발명의 설명·부호의 설명에 설명이 안 들어감.**

---

## 0. 결론 (한 줄)

**발명의 설명 본문(step_08)·부호의 설명(step_18)은 "생성 시점 스냅샷"이다.** 예시도(step_07c)를 그 뒤에 생성/추가하면 시스템은 두 항목을 **stale 배지 + cascade 패널로 표시만** 하고 **자동 재생성하지 않는다**. 사용자가 재생성(cascade/수동)을 실행하지 않으면 이미 작성된 본문에 예시도가 들어가지 않는다. 장치도(1~3)는 step_08 최초 작성 시점에 이미 존재했으므로 설명에 포함된다. ③(순서지정)과는 **무관**(별개·선존재 버그).

핵심 증거: 명세서 조립 `buildSpecification()`(patent.js:14034·14056)에서
- **도면의 간단한 설명** = `extractBriefDescriptions(...)` → **매 조립마다 동적 재계산**(예시도 포함됨) ✅
- **발명을 실시하기 위한 구체적인 내용** = `getFullDescription()`(저장된 step_08) → **스냅샷** ❌
- **부호의 설명** = `outputs.step_18`(저장본) → **스냅샷** ❌

사용자가 지목한 두 항목이 정확히 "저장 스냅샷" 두 곳이다. (동적인 간단한 설명에는 예시도가 들어가므로 사용자가 그건 문제삼지 않음 — 진단과 정합.)

## 1. 예시도 설명이 명세서에 들어가는 경로 (정상 설계)

예시도(step_07c) 생성 시 `outputs.step_07c`에 "이름(번호)" 텍스트가 저장된다(patent.js:142 `_buildConceptOutputText`, 예: `[도 4] UI 화면 예시도\n참조번호: 검색창(31), 결과(32)\n도 4는 …`). 이를 두 본문이 참조한다.

| 본문 | 예시도 참조 방식 | file:line |
|---|---|---|
| **발명의 설명(step_08)** | 프롬프트 말미에 **예시도 블록** 주입: `conceptDiagramTypes.some(svgContent)`면 `도 N: 유형 (참조번호: 31(검색창)…)` + "도 N을 참조하면 형태로 설명" 지시 | patent.js:**4293** (도면 목록 합산 4154–4167, 사용자도면블록 4292) |
| **부호의 설명(step_18)** | `_refSources`에 `outputs.step_07c` 포함 → "이름(번호)" 정규식으로 부호 수집 | patent.js:**4619**(소스), **4622**(정규식) |
| 도면의 간단한 설명(조립 시 동적) | `extractBriefDescriptions`가 `getAutoFigNums('step_07c')`로 예시도 한 줄 설명 추가 | patent.js:**3117–3125** |

→ **설계상 경로는 존재한다.** 즉 step_08·step_18을 **예시도 생성 이후에 (재)생성하면** 예시도 설명이 들어간다. 문제는 그 "이후 재생성"이 자동이 아니라는 점.

## 2. 왜 장치도는 되고 예시도는 누락되나 — 스냅샷/순서

### 2-1. step_08·step_18은 저장 스냅샷
- step_08 생성: `runLongStep`/`_cascadeRunLong` → `outputs.step_08` 저장. 그 시점의 도면(장치)만 본문에 기술됨.
- step_18 생성: `outputs.step_18` 저장. 그 시점 `_refSources`만 반영.
- 명세서 조립은 이 **저장본을 그대로** 싣는다(patent.js:14056 `${desc}`·`${outputs.step_18}`; Word 14066 동일).

### 2-2. 예시도 생성은 "배지만" — 자동 재생성 없음
- `runConceptDiagramStep`(patent.js:5586+) 완료 시: `outputs.step_07c=…`(5692) → `invalidateDownstream('step_07c')`(5694) → `onStepCompleted('step_07c')`(5695).
- `invalidateDownstream`(patent.js:2379–2415)는 **stale 배지 갱신 + `showCascadePanel(...)`(2407) 호출**까지만. **재생성은 사용자가 cascade 패널에서 체크 후 실행해야** 일어난다.
- `onStepCompleted`(patent.js:2418)도 자동 재생성 없음(배지 제거·패널 갱신·미리보기 디바운스뿐).
- 의존성 정의상 `step_07c.MUST = ['step_08','step_18']`(patent.js:2316)이라 cascade 패널엔 두 항목이 뜨지만, **`invalidateDownstream`이 MUST를 `outputs[d]` 존재하는 것만 필터**(patent.js:2382)하므로 — step_08·step_18이 **이미 생성돼 있을 때만** 패널에 뜬다(올바름). 그러나 **사용자가 그 패널을 실행하지 않으면 누락 지속**.

### 2-3. 전형적 사용 흐름이 누락을 만든다
UI 카드 순서는 예시도(7c) → 상세설명(8)이지만(index.html), 예시도는 **선택·수동 추가** 단계라 실무에선:
1. 장치청구 → 장치도면 → **상세설명(step_08)**[도1~3 기술] → … → **부호의 설명(step_18)** 먼저 완료.
2. **나중에** 예시도 유형 추가 → 예시도 생성(step_07c, 도4·5).
3. step_08·step_18 = **stale 배지**만. 재생성 안 하면 도4·5 설명 영구 누락.
→ "장치도는 설명 있고, 예시도만 없음" = step_08·step_18이 **예시도 이전 스냅샷**이기 때문.

> cascade를 실제로 돌리면(`runCascadeRegeneration`, patent.js:2605)는 `topologicalSort`로 `step_07c → step_08/step_18` 순서를 지키므로 정상 반영된다. 즉 **버그는 "반영이 수동·옵트인"이라는 UX/파이프라인 설계**에 있다.

## 3. 부호의 설명 — 재생성해도 누락될 수 있는 2차 원인

step_18을 재생성해도 예시도 부호(31~)가 빠질 수 있는 **독립 실패 모드**:

- `_buildConceptOutputText`(patent.js:145)는 refMap 라벨이 비면 `이름(번호)`가 아니라 **`(번호)`**(이름 없이)로 출력한다.
- step_18 부호 수집 정규식(patent.js:4622)은 `이름\s*(번호)` 즉 **괄호 앞 한글/영문 이름을 요구**한다. → `(31)`만 있으면 **매칭 실패 → 예시도 부호 누락**.
- 라벨은 `_parseConceptRefMap`(patent.js:108–118)이 LLM의 `---REF_MAP---`(번호: 이름)에서 채우고, 누락 시 SVG의 `(번호)`로 **이름 없이** 보강한다(117). → **LLM이 REF_MAP을 빠뜨리면 라벨 공백** → 부호의 설명에 영영 안 들어감.

즉 (2) 스냅샷을 고쳐 재생성해도, **refMap 라벨이 비면 부호의 설명은 여전히 누락**.

## 4. 발명의 설명 — 재생성해도 약할 수 있는 요인 + figNum 정렬 버그

### 4-1. 프롬프트 프레이밍 (과소 기술 위험)
step_08 프롬프트는 "장치 상세설명/방법 금지/장치 도면만"이 강하게 반복되고(patent.js:4179·4218–4221·4284), 예시도 지시는 **말미 블록**(4293)으로 덧붙는다. 재생성해도 LLM이 예시도를 **과소 기술**할 여지가 있다(결정적 누락은 아니나 신뢰도 저하).

### 4-2. ★ 예시도 도 번호 정렬 버그 (잠재·혼재 시 발현)
- patent.js:**4293** `const fn=_conceptFigNums[conceptDiagramTypes.indexOf(ct)]||'?'`
- patent.js:**4158** `_genConceptFigNums=_conceptFigNums.filter((_,i)=>conceptDiagramTypes[i]?.svgContent)`

`_conceptFigNums = getAutoFigNums('step_07c')`는 **생성된(svgContent) 예시도만의 compact 번호배열**(길이 = 생성 개수)이다. 그런데 이를 **full `conceptDiagramTypes` 인덱스**(`indexOf(ct)` / `conceptDiagramTypes[i]`)로 접근한다. → 목록에 **미생성 예시도가 섞이면**(예: 추가만 하고 미생성 유형이 앞에 있음) 인덱스가 어긋나 **도 번호가 `'?'` 또는 엉뚱한 값**으로 주입 → 예시도 설명 누락/오기. (모든 예시도가 생성된 경우엔 우연히 정합되어 발현 안 됨 — 그래서 간헐적.)

## 5. ③(순서지정·무효화)와의 연관 — **무관(별개)**

- 본 진단 기준은 `origin/main`(③ PR #209 **미병합**). 이 상태에서 이미 누락이 발생한다 → **③ 이전부터 존재**.
- ③(PR #209)이 한 일: `computeFigNums`에 예시도 override 예약, `figNumOverride` 필드/UI, **무효화 트리거 추가**(사용자도면 add/remove·예시도 삭제·override 변경 시 `invalidateFigureDependents`). → **"stale 배지만, 자동 재생성 없음"이라는 핵심은 그대로**.
- 따라서 ③는 본 버그를 **유발하지도, 해소하지도 않음**. (③의 무효화 강화는 "언제 stale로 표시할지"를 더 정확히 했을 뿐, "자동 반영"을 추가하진 않음.)
- 단, ③ 머지 후에도 **동일 누락 지속** → 본 수정이 ③와 별개로 필요.

## 7. 수정 방향

1. **[주] 예시도 생성 후 본문 자동 반영.** `runConceptDiagramStep` 완료 시 step_08·step_18이 **이미 존재하면** 자동 재생성(존재 시에만, topo 순 `step_07c→step_08→step_18`). 구현 자원: `_cascadeRunLong('step_08')`·`_cascadeRunShort('step_18')` 순차 호출, 또는 예시도 카드에 **"예시도 설명 반영"** 버튼 + 강조된 cascade 자동 체크/실행. (전면 자동 vs 1클릭 확인은 B1으로 결정.)
2. **[S1] refMap 라벨 폴백 보장.** `_parseConceptRefMap`/`_buildConceptOutputText`에서 라벨 공백 시 **유형 기반 기본 이름**(예: `예시요소(31)`·`UI요소(31)`) 부여 → 부호의 설명 정규식이 항상 추출. 또는 step_18 `_refSources` 예시도 분기에서 **번호만이라도 별도 수집**.
3. **[S2] 예시도 번호 매핑 정합.** 4158·4293에서 `_conceptFigNums`(compact)와 `conceptDiagramTypes`(full)를 **동일 기준(생성된 것만 필터한 배열)으로 zip** — `getAutoFigNums`와 같은 정렬로 인덱스 정합.
4. **[S3] step_08 예시도 지시 강화(선택).** 예시도 설명 지시를 device 프레이밍과 분리·승격(과소 기술 방지), 또는 예시도 상세설명을 step_07c 산출로 분리해 조립 시 결합.
