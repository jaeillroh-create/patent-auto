## 0. 결론 (한 줄)

**⑤ 삽입은 "작동"한다 — 4개 산출물 경로(미리보기·복사·txt·Word) 모두** 【발명을 실시하기 위한 구체적인 내용】에서 **장치 → 예시(step_08c) → 방법 순으로 조립**된다(본인 의도 "상세설명에 삽입" 충족, 단 *조립 시 배치* 방식이지 step_08 본문 물리 병합은 아님). 다만 **꼼꼼함 관점에서 4가지 미흡**: (a) ④를 건너뛰면 **경고 없이 예시도 설명이 누락**(순서 안내·강제 부재), (b) **닫는 정형문(STEP8_SUFFIX, "컴퓨터 판독 가능 매체…")이 장치와 예시/방법 사이에 끼임**(섹션 끝이 아님 — 방법에 선존재, #215가 더 드러냄), (c) **step_08c가 검토(Step13)·반영 루프 밖**이라 예시도 설명이 AI 검토를 안 받음, (d) ③ 도번호 override 시 조립순서와 도 번호가 어긋날 수 있음.

## 1. ★ ⑤ 삽입 현황 — 조립 시 배치(4개 경로 모두 포함)

### 1-1. 어떻게 합치나
- `getLatestConceptDescription()`(patent.js:**3080**) = `outputs.step_08c` 반환.
- 조립부에서 **`[desc(장치), getLatestConceptDescription()(예시), getLatestMethodDescription()(방법)].filter(Boolean).join('\n\n')`** 로 합침.
- 즉 **step_08 본문에 물리적으로 삽입하는 게 아니라**, 출력 조립 시 **장치 다음·방법 앞에 별도 블록으로 배치**한다. → 최종 명세서 【발명을 실시하기 위한 구체적인 내용】에 장치+예시+방법이 모두 들어감.

### 1-2. ★ 모든 출력 경로 포함(꼼꼼 확인) — ✅ 4/4
| 경로 | 함수 | step_08c 포함 |
|---|---|---|
| 미리보기(화면) | `renderPreview`(14293) → `buildSpecification` | ✅ (14324) |
| 복사 | `copyToClipboard`(14326) → `buildSpecification` | ✅ |
| txt 다운로드 | `downloadAsTxt`(14327) → `buildSpecification` | ✅ |
| Word 다운로드 | `downloadAsWord`(14334, 자체 secs) | ✅ |

- ⚠️ **별개**: 간이출원(provisional) 경로(554·573·6252, `pd.desc`/지역 `desc`)는 20-step outputs를 안 쓰는 **별도 기능**이라 step_08c 미포함(주력 명세서 아님 — 영향 적음).
- 예시도 여러 개: step_08c 프롬프트가 전부 "도 N을 참조하면…"으로 기술 → 한 블록으로 조립 ✅.

### 1-3. 본인 의도 부합?
- 의도 "예시도 설명을 **상세 설명에 삽입**" = 【발명을 실시하기 위한 구체적인 내용】에 들어가게 → **충족**(장치·예시·방법이 한 섹션).
- 단 방식이 **조립 시 배치**(step_08c 별도 저장 → 출력 시 합침)다. step_08 *원본*이나 Step13 검토에는 예시도 설명이 안 들어감(§3).

## 2. ★ 미흡 (a) — ④ 건너뛰면 silent 누락 (순서 안내·강제 부재)

- ④(예시도 설명, step_08c)를 **생성하지 않으면** `getLatestConceptDescription()=''` → `filter(Boolean)`로 제거 → **명세서에 예시도 설명이 빠진다.**
- ⛔ 이때 **미리보기·다운로드에 경고가 없다**(grep 확인 — step_08c 미생성 경고 0건). 사용자가 "예시도 상세설명 생성" 버튼을 안 누르면 **조용히 누락.**
- 의존성(STEP_DEPENDENCIES): `step_07c.MUST=['step_08','step_08c','step_18']` 라 예시도 재생성 시 step_08c가 stale로 표시되긴 하나, **최초 생성을 강제·안내하진 않는다.** ①~⑤ 순서 가이드(다음 단계 안내)도 없다.
- (참고: reflect(#210/A1)가 폴백으로 step_08 에 기계적 예시도 단락을 넣을 수 있으나, step_08 생성 경로엔 reflect 미호출이라 타이밍 의존 — DIAG-concept-desc-separation §1-3 참조. 즉 ④ 누락 시 폴백도 불확실.)

---

## 3. ★ 미흡 (c) — step_08c가 검토·반영 루프 밖 (예시도 설명 미검토)

- Step 13(AI 검토) 입력(patent.js:**4805**): `[상세설명] getLatestDescription()`(=step_08 장치) + `[방법 상세설명] getLatestMethodDescription()`(step_12) + `[예시도/개념도 설계] step_07c`(설계 도면). → **`step_08c`(예시도 상세설명 산출물)는 입력에 없다.**
- 즉 AI 검토는 예시도 *설계(step_07c)*는 보지만 **예시도 *설명(step_08c)*은 검토하지 않는다.** applyReview(검토 반영)도 step_08c를 안 건드린다(step_08만).
- → 분리(#215)의 부수효과: 예시도 설명이 **검토·반영·chat 루프에서 분리**됨. 품질 검토를 못 받음. (B 정리/후속 단계에서 step_13 입력에 step_08c 추가 검토.)

## 4. ★ 미흡 (b) — 닫는 정형문(STEP8_SUFFIX) 위치 (정합)

- `getFullDescription()`(patent.js:**3100**) = `STEP8_PREFIX + 장치(step_08) + STEP8_SUFFIX`.
  - PREFIX = "이하, 본 발명의 실시예를 첨부된 도면을 참조하여 상세하게 설명한다."(여는 정형문)
  - SUFFIX = "본 발명에 따른 방법들은 …컴퓨터 판독 가능 매체에 기록될 수 있다…"(★닫는 정형문)
- 조립 `[desc(=PREFIX+장치+SUFFIX), 예시, 방법]` → 최종 순서:
  `여는정형문 → 장치 → ★닫는정형문 → 예시 → 방법`
- ⛔ **닫는 정형문이 섹션 끝이 아니라 장치와 예시/방법 사이에 끼인다.** 예시·방법 설명이 "컴퓨터 판독 가능 매체…" 닫는 문단 *뒤*에 와서 정합이 어색하다.
- ★ 이는 **#215 이전부터 방법(step_12)에 있던 선존재 문제**(기존 `${desc}${method}`도 SUFFIX 뒤에 method). #215의 예시도 삽입이 이를 더 드러냄. 이상적 순서: `여는정형문 → 장치 → 예시 → 방법 → 닫는정형문`.

## 5. ★ 미흡 (d) — ③ 도번호 override 시 조립순서 ↔ 도 번호 불일치 (엣지)

- 정상 번호(장치 1-4 < 예시 5-6 < 방법 7+)면 조립 순서(장치→예시→방법) = 도 번호 오름차순 ✅.
- 그러나 ③ `figNumOverride`로 예시도를 **장치 사이 번호(예: 도 2)** 에 두면, 조립은 여전히 장치(1-4) 다음 예시(2)라 **도 번호 오름차순이 깨진다**(도1,2,3,4 다음 도2). 흔치 않은 엣지지만 정합 관점 기록.
