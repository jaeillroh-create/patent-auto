## 0. 결론 (한 줄)

**#210 reflect 로직은 정상 작동한다(머지 무손상, 자동 반영 테스트 18건 통과).** 다만 **reflect는 "예시도 생성 시점"에만 호출**되고 **openProject(프로젝트 열기)·renderPreview·buildSpecification 에서는 호출되지 않는다.** → 버그가 나타나던 **기존 프로젝트(예시도가 이미 생성돼 있는 사건)를 열면 reflect가 한 번도 안 돌아** 화면/다운로드에 예시도 설명이 여전히 누락된다. (새로 예시도를 생성하면 반영된다 — 사용자는 기존 사건을 보고 있을 것.)

그리고 **Step 13(AI 검토)은 입력에 `outputs.step_07c`(예시도)를 받지 않는다** → 예시도 설명/부호 누락을 **검토 자체가 못 본다.** 두 누락(반영·검토)은 **한 뿌리**: 예시도(step_07c)가 명세서 스냅샷 lifecycle(열기·검토·조립)에 배선돼 있지 않다.

## 1. ★ 최우선 — #210이 왜 화면서 안 도나 (호출? 계층? 머지?)

### 1-1. 머지로 깨지지 않았다 (작동 확인)
- `reflectConceptsToSpec` 본체(patent.js:**192–221**) 머지 후 무손상. APPEND·멱등·계층 우선순위 보존 로직 그대로.
- 머지 트리에서 **자동 반영 테스트 18건 전부 통과**(`patent-concept-spec-autofill.test.js`). → **호출되면 정상 동작.**

### 1-2. ★ reflect는 "생성 시점"에만 호출된다 (호출 범위 문제)
호출부는 **딱 2곳**, 둘 다 예시도 **생성** 경로다:
- `runConceptDiagramStep`(patent.js:**5876**) — 예시도 수동 생성 직후.
- `_cascadeRunConceptDiagram`(patent.js:**2977**) — 연쇄 재생성 시.

**호출되지 않는 곳(핵심):**
- `openProject`(patent.js:**643**) — 사건을 열 때. 686행에서 `conceptDiagramTypes`(svgContent 포함)·`outputs`(예시도 없는 step_08) **복원만** 하고 **reflect 미호출**.
- `renderPreview`(patent.js:**14191**) / `buildSpecification`(patent.js:**14218**) — 미리보기/다운로드 조립 시 미호출.

### 1-3. ★ 그래서 "기존 프로젝트"는 영영 안 돈다
버그가 나타나던 시나리오 = **step_08(장치 설명) + 예시도(step_07c) 가 이미 둘 다 존재하되, step_08엔 예시도가 없는 사건**(예시도를 step_08 작성 *뒤에* 추가했기 때문).
- 그 사건을 **열면** openProject가 복원만 하고 reflect를 안 부른다 → step_08은 여전히 예시도 없음 → **화면/다운로드 누락 지속.**
- 사용자가 #210 배포 후 그 사건을 열어 확인 → "안 된다". (reflect를 다시 돌리려면 **예시도를 재생성**해야 함 — 직관에 반함.)

> 즉 #210은 **"앞으로 새로 생성하는 예시도"** 만 자동 반영하고, **"이미 그려둔 예시도"(=버그 그 자체)** 는 손대지 못한다. 사용자가 본 게 바로 후자.

### 1-4. 새 생성 경로는 정상 (대조)
step_08 존재 상태에서 예시도를 **새로** 생성하면: 5876 reflect 실행 → step_08/step_18 APPEND → 토스트 "예시도 설명 자동 반영 N건" → 미리보기·다운로드 반영. (이 경로는 동작하므로, 사용자가 "전혀 안 된다"면 기존 사건을 보는 것.)

## 2. 반영돼도 buildSpecification·다운로드가 싣나 — 싣는다 (경로는 안 끊김)

reflect가 **돌기만 하면** 조립은 정상이다:
- `buildSpecification`(patent.js:14218·14240): 발명을 실시하기 위한 구체적인 내용 = `getFullDescription()`→`getLatestDescription()`(저장 step_08/09/13_applied), 부호의 설명 = `outputs.step_18`.
- reflect는 **존재하는 모든 상세설명 계층**(step_08·step_09·step_13_applied)에 APPEND하고(199–208), 파생 계층 timestamp만 bump해 **getLatestDescription 우선순위를 보존**(207) → 다운로드가 읽는 계층에 예시도가 들어 있다.
- step_18도 APPEND(211–219) → `outputs.step_18` 읽는 조립에 반영.

→ **끊기는 지점은 "buildSpecification"이 아니라 "reflect가 애초에 호출되지 않는 openProject"다.**

## 4. ★ Step 13(AI 검토)이 도면 설명 누락을 보나 — 예시도는 못 본다

### 4-1. Step 13 입력에 step_07c 없음 (구조적 사각)
step_13 프롬프트 입력(patent.js:**4747**):
```
[청구범위] step_06, step_10
[상세설명] getLatestDescription()  ← step_08 계층
[방법 상세설명] getLatestMethodDescription()
[도면 설계] outputs.step_07  ← ★ 장치 도면만! (step_07c 예시도 없음)
[원본 발명 내용] inv
```
→ **예시도(step_07c)·예시도 부호(31~99)가 Step 13에 전달되지 않는다.**

### 4-2. 검토 항목도 예시도를 겨냥하지 않음
- **[10] 도면 부호 정합성**(4723–4731): "상세설명 참조번호 ↔ **도면 설계(step_07)**" 대조. 입력이 장치 도면뿐이라 **예시도 부호(31~)는 검토 불가**(오히려 31~을 "도면 미정의"로 오인할 소지).
- **[1] 청구항 뒷받침 / [7] 발명 반영 완전성**: 청구항↔상세설명 중심. "예시도가 상세설명에 기술됐는지"를 보는 항목 **부재**.
- 즉 **"예시도 설명/부호 누락"은 Step 13의 검토 범위 밖** → 검토가 잡지 못한다.

## 7. 수정 방향

### A. 기존 사건도 자동 반영 (요청① 핵심)
- **openProject 복원 직후 `reflectConceptsToSpec()` 1회 호출**(patent.js:686 부근). reflect는 멱등·본문 보존이므로 안전 — 기존 사건을 열면 예시도가 step_08/step_18에 즉시 반영된다.
- (보강) **renderPreview/buildSpecification 진입 시에도** 멱등 reflect 1회(지연 반영) — 다운로드 직전 보장. 단 "read 중 mutate" 회피 위해 openProject 반영을 1순위로.
- (대안/보완) 예시도 카드에 **"예시도 설명 반영" 수동 버튼** — 자동 실패 시 사용자 보정 경로.

### B. Step 13에 예시도 포함 (요청② + 연결)
- step_13 입력 `[도면 설계]`에 **`outputs.step_07c` 추가**(또는 별도 `[예시도]` 블록). 예시도 부호(31~99) 인지.
- 검토 항목 **[10] 도면 부호 정합성**을 예시도 부호까지 확장하거나, **신규 항목 "예시도 설명/부호 정합"**(예시도가 상세설명에 "도 N을 참조하면 …" 형태로 기술됐는지, 31~ 부호가 부호의 설명에 있는지) 추가.
- 이로써 검토가 예시도 누락을 잡고, 보완 제안 → step_13_applied 반영까지 이어진다.
