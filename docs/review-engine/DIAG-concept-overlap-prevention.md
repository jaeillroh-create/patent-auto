# DIAG — 예시도(Step 7c) 부호선/연결선 겹침 — 근본 원인 + 생성 단계 예방

> 브랜치: `review-engine/diag-concept-overlap-prevention` · READ-ONLY 진단(코드 0)
> 결론 한 줄: 겹침이 반복되는 건 우연이 아니라 **Step 7c 생성 단계에 겹침 예방 장치가 0개**이기 때문이다 — ① 생성 프롬프트 SVG 규칙이 "선이 다른 요소를 가로지르지 마라/간격을 둬라"를 **말하지 않고**, ② 자기검증 4항목에 **겹침 점검이 없으며**, ③ 좌표를 자동배치·충돌해소하는 **레이아웃 엔진이 없고**(LLM 수기 좌표), ④ 생성 직후 **자동 검증/정련이 없다**(P5는 수동 버튼). 반면 **장치 도면(step_07)은 ①프롬프트 "배치 품질 규칙(렌더링 겹침 방지)" + ③layoutGraph 자동배치 + 코드 충돌검사**를 다 갖춰 같은 문제가 없다. → ★ **사후 P5 땜질이 아니라, step_07의 예방 모델을 prompt-level로 이식 + P5 자동 1회**가 정답.

---

## 1. 겹침 근본 원인 — 생성 단계 "예방 0" (step_07 대비)

| 예방 장치 | **step_07 장치도면(mermaid)** | **step_07c 예시도(SVG-direct)** |
|-----------|------------------------------|--------------------------------|
| 프롬프트 겹침 방지 규칙 | ✅ "★★★ 배치 품질 규칙 (렌더링 겹침 방지)"(3990): 한 행 3개 초과 금지·흐름순 배치·번호 오름차순, "연결선 교차→가독성 저하"(3961) | ❌ **없음** — SVG 기술규칙 8개(5548~5556)는 viewBox·stroke·font·번호표기만. "리더선·연결선이 다른 요소를 가로지르지 마라/간격" **지시 부재** |
| 자기검증(self-check) | (레이아웃은 코드가 보장) | ⚠️ 있으나(5649) 4항목=색상·~부박스·a/b접미·step_07차별화 — ★ **겹침 점검 없음** |
| 프로그램 자동배치 | ✅ `layoutGraph`(8222)로 좌표 결정·디컨플릭트 | ❌ **없음** — LLM이 좌표를 손으로 찍음(수기 SVG) |
| 코드 충돌 검사 | ✅ 리더라인 교차 검사(11055 `intersects` bbox 검사) + PPTX 충돌상수(6026~6048 BOX_GAP·"겹침 보정 후 렌더") | ❌ **미적용**(그 코드는 mermaid 전용, 개념 SVG엔 안 돎) |
| 생성 직후 자동 검증/정련 | (코드가 보장) | ❌ **없음** — 생성→바로 출력. P5 정련은 **수동 [정련] 버튼**(2133)뿐 |

→ ★ **개념 SVG는 "겹치지 말라"는 말도, 겹침을 푸는 코드도, 겹침을 잡는 검증도 없다.** LLM은 충돌 제약 없이 좌표를 찍으므로 **리더선(예: 32)이 연결선·박스를 가로지르는 게 기본 결과**다. 그래서 도면마다 반복된다.

> ★ 캐스케이드 프롬프트는 더 빈약: SVG 규칙이 **한 줄**(viewBox·stroke·font·번호)뿐이고 **자기검증·겹침 지시가 아예 없다**(메인보다 약함) — 연쇄 재생성 시 겹침이 더 잘 난다.

## 2. 현재 생성·검증 구조 (예방 지점 매핑)

```
[생성] runConceptDiagramStep(프롬프트 5523~5653) / _cascadeRunConceptDiagram(축약)
   프롬프트: 시각형태·금지(블록도)·SVG 스타일규칙 + 자기검증 4항목(★겹침 없음)
        │   (자동배치·충돌제약 없음 — LLM 수기 좌표)
        ▼
[자기검증] 색상·~부·a/b·step_07차별화만 점검 → ★ 겹침 통과
        ▼
[출력] _parseConceptResult → svgContent 저장 → 바로 렌더/다운로드   ← ★ 자동 검증/정련 없음
        ┄┄┄(단절)┄┄┄
[정련 P5] Patent.refineConceptDiagramByNum — ★ 사용자가 카드 [정련] 버튼을 눌러야 발동(수동)
```

★ **예방 지점이 한 곳도 없다.** 생성 프롬프트는 겹침을 막지 않고, 자기검증은 겹침을 안 보고, 출력 전 자동 검사도 없다. 유일한 겹침 처리(P5)는 **생성과 단절된 수동 사후 단계**다.

## 3. 생성 단계 검증 옵션 (prompt-level 예방 중심) + 트레이드오프

| 옵션 | 방법 | 장점 | 한계/비용 |
|------|------|------|-----------|
| ★ **A. 프롬프트 겹침 규칙** | 개념 SVG 규칙에 "리더선은 짧고 곧게, 다른 요소를 가로지르지 마라 / 요소 간 최소 간격 / 텍스트 박스 겹침 금지 / 번호는 가리키는 요소 옆 빈 공간에"를 추가(step_07 "배치 품질 규칙" 이식) | 가장 싼 prompt-level 예방, 근본 지점, 호출 0 추가 | LLM 준수 불완전(보장 아님) — B·C로 보강 |
| ★ **B. 자기검증에 겹침 항목** | 자기검증(5649)에 "출력 전: 모든 리더선/연결선이 다른 요소와 교차하지 않는지 점검하고, 교차하면 경로·좌표를 수정하라" 추가 | 싸고 1패스 자가수정, 호출 0 추가 | LLM의 좌표 기하 추론은 약함(텍스트로 교차 판단 부정확) |
| ★ **C. 생성 직후 P5 자동 1회** | 생성 끝나면 `refineConceptDiagram`을 **자동 1회** 호출(비전이 실제 렌더를 보고 겹침 수정). P5 재사용 | ★ **가장 신뢰도 높음** — 비전은 "선이 겹치나"를 실제로 봄(좌표추론보다 정확). P5·번호보존가드 그대로 | 생성당 비전 호출 +1(비용·지연). 토글/예산 가드 권장 |
| ✗ **D. 코드 선분교차 검사** | SVG의 `<line>/<path>` ↔ `<rect>/<text>` bbox 교차를 코드로 계산해 플래그·재생성 | 결정적 | ★ 고비용·취약 — 임의 SVG 기하(곡선 path·텍스트 bbox) 파싱이 어렵고 형태 다양성에 부서짐. C(비전)가 같은 목표를 더 견고히 달성 → 비권장 |

> 원칙: **A·B는 "예방"(생성이 처음부터 안 겹치게), C는 "안전망"(그래도 남으면 비전이 잡음).** A·B는 LLM 준수가 불완전하므로 C가 net으로 보완한다. D는 노력 대비 이득이 낮고 C로 대체된다.

## 4. 정돈할 것

1. ★ **메인·캐스케이드 프롬프트 분산(P4 미완)** — SVG 규칙·자기검증·(신규)겹침 규칙이 메인에만 있고 캐스케이드는 한 줄. → **겹침 규칙을 공유 상수**(`CONCEPT_PURPOSE_RULES` 옆에 `CONCEPT_SVG_RULES`)로 빼서 **양쪽 일관 주입**(P4 일부 완성).
2. ★ **P5 수동 → 자동 1회 배선** — 생성 직후 `refineConceptDiagram` 자동 호출(옵션 C). 수동 [정련] 버튼은 추가 정련용으로 유지.
3. **step_07 예방 모델 차용** — "배치 품질 규칙(렌더링 겹침 방지)"(3990)·충돌상수(6026~6048)는 검증된 자산. 개념 SVG용으로 번안(좌표 자동배치는 불가하나 "간격·교차 금지" 규칙은 이식 가능).
4. **자기검증 항목 정렬** — 개념 자기검증(5649)에 겹침 항목 추가, 캐스케이드에도 동일 적용.
5. (별건) **코드 충돌검사(11055)는 mermaid 전용** — 개념 SVG엔 안 돎. D를 안 한다면 그대로 둠.

## 5. 권장 방향

**A(프롬프트 겹침 규칙) + B(자기검증 겹침 항목) = prompt-level 예방(필수·저비용), 공유 상수로 메인·캐스케이드 일관.**
**+ C(생성 직후 P5 자동 1회) = 신뢰 안전망**(비전이 실제 겹침을 보고 수정, 이미 있는 P5·번호보존가드 재사용).
**D(코드 선분교차)는 비권장**(취약·고비용, C로 대체).

> 한 줄: **"안 겹치게 써라"(A·B 프롬프트 예방) + "그래도 겹치면 비전이 고친다"(C 자동 P5).** 사후 수동 땜질(현행)에서 **생성 단계 예방 + 자동 안전망**으로 전환.

## 6. 핵심 질문 — 직답

- **부호선 겹침 근본 원인** → **생성 단계 겹침 예방이 0개.** 프롬프트가 선 교차/간격을 안 말하고(SVG 규칙 5548~5556), 자기검증이 겹침을 안 보며(5649), 자동배치 엔진이 없고(수기 SVG), 자동 검증도 없다. LLM이 충돌 제약 없이 좌표를 찍어 **리더선이 연결선·박스를 가로지르는 게 기본** → 반복.
- **생성 단계에 겹침 방지·검증 있나** → **없다.** (대조: step_07은 "배치 품질 규칙" + layoutGraph + 충돌검사로 예방.)
- **★ 생성 단계 검증 방법** → A 프롬프트 규칙 + B 자기검증 항목(prompt-level 예방) + C 생성 직후 P5 자동 1회(비전 안전망). D 좌표검사는 비권장.
- **사후 정련(P5) → 생성 자동화 가능한가** → **가능.** 생성 직후 `refineConceptDiagram` 자동 1회(C). 비용은 비전 호출 +1(토글·예산 가드).
- **정돈할 코드** → 메인·캐스케이드 겹침/SVG 규칙 공유 상수화(P4), 자기검증 겹침 항목, P5 자동 배선, step_07 예방 모델 차용.
