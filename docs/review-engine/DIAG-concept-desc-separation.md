# DIAG — B1 후에도 예시도 설명 누락 + 예시도 상세설명 분리 설계

> 브랜치: `review-engine/diag-concept-desc-separation` · 기준: `origin/main`(0f184f1, #214 포함) · 코드 변경 0
> 증상: B1(#214)로 step_08 프롬프트에 예시도 동작·구현 지시를 넣었으나, Step 8 상세설명 생성 시 **장치 구성(100~)만** 나오고 **예시도(도 5·6, 31~)는 여전히 누락.** (통합 도면 순서는 정상: 도 1-4 장치, 도 5-6 예시도.)

---

## 0. 결론 (한 줄)

**B1이 약한 근본 이유 = "단일 LLM 호출 과부하".** step_08은 **한 번의 호출**(`runLongStep→buildPrompt('step_08')`)로 장치+예시도를 모두 쓰는데, 예시도 블록은 **8개 이상의 ★★★ 장치 메가룰 중 맨 끝 1개 섹션**이고 프롬프트 전체가 "이것은 **장치** 상세설명이다"(4378)로 지배된다 → LLM이 장치에 집중하고 예시도를 떨군다. 게다가 **step_08 생성은 reflect를 호출하지 않아**(reflect는 예시도생성·열기 시점만) 폴백도 없다. **본인 해법(분리)이 정답이다 — 예시도 상세설명을 별도 단계(step_08c)로 분리**하면, 이미 존재하는 "방법 상세설명(step_12)이 장치 상세설명(step_08)과 분리된" 패턴을 그대로 미러링해 누락을 **구조적으로 차단**한다.

## 1. ★ B1이 왜 약한가 (또 누락)

### 1-1. 입력 경로는 정상 — 출력(LLM)이 떨군다
- 예시도 블록(patent.js:**4493**)은 `conceptDiagramTypes.some(svgContent)` 게이트로, 생성된 예시도가 있으면 **입력에 포함된다.** [예시도 설계](step_07c 전문)도 데이터 라인(4494)에 주입된다. → **입력은 들어간다.**
- 즉 svgContent 게이트·입력 경로 문제가 **아니다.** LLM이 **출력에서 누락**한다.

### 1-2. ★ 단일 호출 과부하 + 장치 지배 프레이밍 (근인)
- step_08 = **단일 호출**: `runLongStep('step_08')` → `App.callClaudeWithContinuation(buildPrompt('step_08'), pid)`(patent.js:**5005**). 한 프롬프트·한(이어쓰기) 호출로 장치 전체 상세설명을 생성.
- 그 프롬프트는 **장치 메가룰로 가득**: `★★★` 섹션이 **8개 이상**(용어통일·파라미터명세·서버단말·도면범위·설명순서·앵커뒷받침·참조번호통일 …), 그리고 "⛔ 이것은 **장치** 상세설명이다"(4378), "⛔⛔⛔ 도면 범위 제한 위반 시 전체 무효"(4417) 등으로 **장치에 압도적으로 지배**된다.
- 예시도 블록(4493)은 그 **맨 끝의 1개 섹션**. B1이 그 섹션을 강화(불릿 1개 추가)했어도, **장치 지배 단일 호출에서 LLM이 후순위로 떨구는 구조**는 그대로다. → 누락 반복.

### 1-3. step_08 생성이 reflect를 호출하지 않음 (폴백 부재)
- `reflectConceptsToSpec` 호출부(patent.js): 200(정의)·**699(openProject A1)**·**2996(cascade)**·**5908(runConceptDiagramStep)**. → **runLongStep('step_08')에는 없다**(확인).
- 따라서 "예시도 먼저 생성 → step_08 생성"(B1 권장 순서) 시: 예시도 생성 때 reflect 돌지만 step_08 부재라 no-op → step_08 생성은 B1(실패)에만 의존 → **device-only.** reflect가 step_08 생성 직후 폴백으로 돌지 않아 누락이 그대로 남는다.

> 정리: 입력은 정상, **단일 호출 과부하 + 장치 지배**로 LLM이 출력에서 누락, **폴백(reflect)도 step_08 생성 경로엔 없음** → B1로 못 막는다.

## 2. ★ 현재 Step 8 구조 — 장치+예시도 한 호출. 단, "방법"은 이미 분리(선례)

- **장치 상세설명 = step_08**(C1), **방법 상세설명 = step_12**(C3) 는 **이미 별도 단계**다(STEP_NAMES 242). 각각 `runLongStep`로 **독립 생성**되고, 별도 accessor(`getLatestDescription` / `getLatestMethodDescription`)로 접근, buildSpecification에서 **함께 조립**된다(patent.js:**14273**: `${desc}`(장치) + `${getLatestMethodDescription()}`(방법)).
- 그런데 **예시도 상세설명은 별도 단계가 없다.** step_08(장치)의 **하위 섹션(4493)** 으로 끼워져 있어 §1의 과부하에 깔린다.
- → **방법(step_12)이 장치(step_08)와 분리된 그 패턴을, 예시도에도 그대로 적용**하면 된다(아키텍처 선례 존재 = 저위험).

## 3. ★ 분리 설계 (본인 해법) — step_08c "예시도 상세설명" 전용 단계

### 3-1. 신규 단계 `step_08c` (예: "C1c. 예시도 상세설명")
- STEP_NAMES에 `step_08c:'C1c. 예시도 상세설명'` 추가(step_08·step_12와 동급).
- **전용 생성** — focused 프롬프트(장치 메가룰 없음, 예시도만):
  - 입력: `[예시도 설계]`(step_07c: refMap 31~99 + briefDesc), `[장치 도면 설계]`(step_07: 장치 구성 100~), `[장치 청구범위]`(step_06), `[장치 상세설명]`(step_08 발췌 — SW→HW 동작 근거).
  - 지시: "각 예시도(도 N)를 '도 N을 참조하면, …' 형태로, 그 요소(31~99)가 **장치 구성(100~)에 의해 어떻게 동작·구현**되는지(소프트웨어→하드웨어, §42 실시가능성), **실질적·예시적 시나리오**로 기술하라. 장치 구성요소는 [장치 상세설명]과 동일 명칭·참조번호로." (= #214 B1 지시를 **이 전용 프롬프트로 이전**, 장치 경쟁 제거.)
  - 생성: `runLongStep('step_08c')` 재사용 or 전용 러너. 길이 짧으므로 단일 호출로 충분(예시도 2~3개).
- **저장**: `outputs.step_08c`(텍스트). 검토 반영 계층은 일단 단순(step_08c 직접) — 필요 시 step_08c_applied 확장.

### 3-2. 조립 (buildSpecification) — 장치 → 예시 → 방법 (도 번호 순)
- 【발명을 실시하기 위한 구체적인 내용】 = `장치(step_08)` + **`예시도(step_08c)`** + `방법(step_12)`.
- 도 번호 자연 정렬: 장치 1-4 < 예시 5-6 < 방법 7+ → device→concept→method 순이 곧 도 번호 오름차순.
- patent.js:**14273**(copyToClipboard)·**14283**(downloadAsWord) 두 조립부에 `outputs.step_08c`(또는 accessor) 슬롯 삽입.

### 3-3. UI — "예시도 상세설명 생성" 버튼
- Step 7c 카드(index.html:1045, `btnStep07c` 아래) 또는 Step 8 카드(1070)에 **"예시도 상세설명 생성"** 버튼 추가(`onclick="runLongStep('step_08c')"` 또는 전용).
- (선택) `runConceptDiagramStep` 완료 직후 step_08이 있으면 자동 트리거(편의) — 단 중복 생성 가드.

### 3-4. 의존성 (STEP_DEPENDENCIES)
- `step_07c.MUST` 에 `step_08c` 추가(예시도 바뀌면 예시도 상세설명 무효화). `step_06`·`step_07` 변경도 SHOULD.
- step_08c 자체는 step_18(부호의 설명)에 SHOULD(예시도 부호 반영).

## 4. ★ reflect/B1 정리 (분리 시 중복 제거)

분리(step_08c)가 도입되면 기존 두 장치는 **중복·약체**가 되므로 정리:

| 기존 | 역할 | 분리 후 |
|---|---|---|
| **B1 예시도 블록**(step_08 프롬프트 4493) | 단일 호출에 예시도 끼워넣기(약함) | ★ **제거** — step_08은 장치 전용으로 환원(과부하 해소). 지시는 step_08c 프롬프트로 이전. |
| **reflect**(#210·A1, step_08/18에 기계적 예시도 단락 APPEND) | 예시도생성·열기 시 폴백 주입(기계적·외형) | ★ **은퇴**(step_08c가 풍부한 설명 담당). step_08 APPEND 중복 제거. |
| **부호의 설명(step_18)** 예시도 부호 | reflect가 31~ APPEND + _refSources가 step_07c 읽음(4774) | step_18 생성이 이미 step_07c·step_08c 읽도록 유지(reflect 없이도 부호 포함). |

- → **분리 = reflect·B1 정리의 정당한 계기.** 셋(B1·reflect·간단설명)이 따로 놀던 것을 **step_08c 단일 책임**으로 통합. 중복·충돌 제거.
- ⚠️ 단 **부호의 설명(step_18) 경로는 유지**해야 함(예시도 부호 31~ 누락 방지). step_18 입력에 step_07c(또는 step_08c) 포함 확인.

## 8. 검증 관찰 포인트(수정 후)
- 예시도 생성 → **"예시도 상세설명 생성"** → 명세서 【발명을 실시하기 위한 구체적인 내용】에 **장치(도1-4) 다음 예시도(도5-6) 설명이 빠짐없이** 들어가나(누락 0).
- 예시도 설명이 외형뿐 아니라 **장치 구성(프로세서(120) 등)에 의한 동작·구현(SW→HW)·실질 시나리오** 인가.
- 장치 상세설명(step_08) 회귀 0(예시도 블록 제거로 오히려 장치 집중 향상).
- 부호의 설명(step_18)에 예시도 부호(31~) 유지(reflect 은퇴 후에도).
- 중복 단락(reflect+step_08c) 0.
