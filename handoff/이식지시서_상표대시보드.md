> **목표**: 상표 출원 대시보드(`#trademark-sub-application`)를 특허 대시보드와 동일한 디자인 언어로 리디자인.
> **시각 레퍼런스**: `patent_dashboard_redesign.html` (특허 파일럿 — stat 카드·배지·카드형 표 패턴 그대로).
> **전제**: STEP 1·2·3(특허) 완료. 색은 `--dt-*`/`--color-*` 토큰만. hex 하드코딩 금지.
> **브랜치**: `feature/redesign-trademark-dashboard`

## 0. 특허와 결정적으로 다른 점 (먼저 인지)

| | 특허 대시보드 | 상표 대시보드 |
|---|---|---|
| 마크업 위치 | `index.html`(정적) | **`trademark.js`의 `innerHTML` 템플릿(동적)** |
| 수정 대상 | index.html + patent.css | **`trademark.js`(렌더 함수) + `trademark.css`** |
| 목록 렌더 | patent.js `dashProjectList` | `trademark.js` `TM.loadProjectList()` → `#tm-project-list` |

→ **상표는 index.html을 거의 안 건드리고, `trademark.js`의 템플릿 문자열을 고친다.**

## 1. ⚠️ STEP 2가 놓친 하드코딩 (이번에 같이 정리)

STEP 2는 `trademark.css`만 정리했고 **`trademark.js`의 인라인 스타일은 손대지 않았다.** `TM.renderDashboard`(line ~664~) 템플릿에 아래 잔재가 있음 — **반드시 토큰화**:

| 위치 | 현재 | → 치환 |
|---|---|---|
| 새 프로젝트 버튼 box-shadow | `rgba(59, 130, 246, 0.3)` ← **시안색 #3B82F6!** | `var(--dt-sh-sm)` 또는 brand 기반 그림자. **59,130,246 절대 유지 금지** |
| KIPRIS 안내 박스 | `background:#F7FBFF; border:1px solid #C9DEFE` | `var(--dt-brand-pale)` / `var(--dt-brand-mid)` |
| 안내 본문 텍스트 | `color:#002966` | `var(--dt-brand-deep)` (STEP 1 신규) 또는 `var(--dt-g700)` |
| 컨테이너 | `max-width:1400px` | `var(--dt-max-w)` (1120) |
| 다수 인라인 스타일 | 산발 | `.tm-*` 클래스로 이전 (trademark.css) |

> `grep 'rgba(59, *130, *246'` 와 `grep '#3[0-9A-Fa-f]82f6'` 로 시안색 잔재 0 확인.

## 2. Stat 4 신설 — 실제 status enum 기준 (임의 생성 금지)

상표 프로젝트의 **실제 status**(`TM.getStatusLabel`)는 4종뿐:
```
draft(작성 중) · searching(검색 중) · documenting(문서 작성) · completed(완료)
```
→ Stat 4 카드를 이 실제 enum으로 구성:

| 카드 | 산출 |
|---|---|
| 전체 | 프로젝트 총 건수 |
| 작성 중 | status === 'draft' |
| 진행 중 | status === 'searching' \|\| 'documenting' (검색+문서 합산) |
| 완료 | status === 'completed' |

- `TM.loadProjectList()`가 받아오는 프로젝트 배열에서 카운트 계산 → stat 카드 textContent. **신규 API 호출·하드코딩 숫자 금지.**
- 특허 #129와 동일 원칙: **실재하지 않는 상태 만들지 말 것.** (위 4개가 실제 enum이므로 그대로 사용)

## 3. 상태 배지 (목록 표)

`TM.loadProjectList()`의 행 렌더에서 status를 색 배지로. trademark.css에 추가(특허 `.pt-badge`와 동일 구조, `.tm-` 접두):
```css
.tm-badge { display:inline-flex; align-items:center; gap:4px; height:24px; padding:0 10px;
  border-radius:var(--radius-full); font-size:var(--font-size-small); font-weight:700; }
.tm-badge.s-draft       { background:var(--color-primary-light); color:var(--color-primary-hover); }
.tm-badge.s-searching   { background:var(--color-warning-light); color:var(--color-warning); }
.tm-badge.s-documenting { background:var(--color-warning-light); color:var(--color-warning); }
.tm-badge.s-completed   { background:var(--color-success-light); color:var(--color-success); }
```
- `TM.getStatusLabel(status)` 라벨은 그대로 쓰고, 클래스만 status별로 매핑.

## 4. 목록 표 (구조 보존 + 스타일 교체)

- `#tm-project-list` 컨테이너 id, `TM.loadProjectList()`가 그리는 **표 골격·컬럼(상표명/유형/상태/수정일/작업) 유지.**
- thead 스타일·행 hover·셀 구조만 특허 패턴으로 교체 (`--color-bg-tertiary` 헤더, hover `--color-primary-light`).
- 상표명 셀: 상표명(굵게) + 부제로 **유형/단계 진행률** 표시 가능(데이터 있으면). 진행률은 `TM.getProgressPercent()` 류가 프로젝트별로 산출 가능한 경우만, 아니면 생략 (임의 생성 금지).

## 5. 좌측 액션 컬럼 — 구조 유지, 토큰화

- 기존 240px 컬럼(제목·"새 프로젝트"·"설정"·KIPRIS 안내) 유지.
- 인라인 스타일 → `.tm-action-col`, `.tm-panel-title`, `.tm-ref-card` 클래스.
- 버튼은 운영 `.btn .btn-primary` 재사용. §1의 box-shadow 하드코딩 제거.
