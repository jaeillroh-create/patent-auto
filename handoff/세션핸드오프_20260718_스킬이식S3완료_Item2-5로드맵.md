### 2.5 ✅ S3 구현 상세 (Item 1 — PR #224 머지됨)

**무엇:** 두 직사각형 박스가 **마주보는 변의 좌표 범위가 겹치면**, 연결선을 겹침밴드 **중앙에 직선**으로 접속(스킬 §8.2 "직선 우선 + 겹침밴드 중앙 접속").

**어디:** `patent/modules/07-diagram-engine.js`
- `_facingOverlapBand(fromBox,toBox)` **신설** (현재 07:1410) — 마주보는 변 겹침 판정. 반환 `{axis:'h'|'v', fromDir, toDir, center}` 또는 `null`(대각/비겹침).
- `_snapRouteToShapeAnchors(...)` (07:1427) 내부, toAnc 계산 직후에 **축약 블록** 삽입 — 공유 헬퍼라 **SVG/PPTX/이미지 렌더 전 경로에 자동 전파**.

**4중 가드 (하나라도 불충족 → 기존 직교 라우팅 그대로):**
1. 양쪽 `_shapeType`이 `'box'` (곡면 shape: cloud/database/monitor 등 제외 — 제거 시 재렌더 루프 유발 이력 있음)
2. 겹침밴드 존재 (`_facingOverlapBand !== null`)
3. 직선 비퇴화 (`|Δx|+|Δy| > _ct`, `_ct`=coordTol: SVG=1px, PPTX≈`PPTX_PAD/ROUTE_PAD`)
4. 다른 박스 관통 없음 — `_others.every(b=>!_segmentIntersectsBox({x:sfx,y:sfy},{x:stx,y:sty},b,_ct))`

**★ 좌표계·식별 함정 (이번에 실제로 잡은 잠재 버그 — 후속 작업 시 반드시 인지):**
- `nodeBoxes` 항목: `{x,y,w,h,cx,cy}` = **라우팅 박스** / `{_sx,_sy,_sw,_sh,_shapeType}` = **타이트 shape 박스**. 앵커는 `_s*` 우선, 장애물 검사는 라우팅 박스(보수적).
- `allBoxArr = Object.entries(nodeBoxes).map(([k,v])=>({...v,id:k}))` — **복사본**이라 참조 동일성 없음. 호출부는 raw `fb`/`tb`(**id 없음**)를 넘김 → id 기반 제외는 **소리 없이 죽은 코드**가 됨. 그래서 from/to 제외는 **좌표 동일성**(`b.x===fromBox.x && …`)으로 구현했다. 이 패턴을 바꾸지 말 것.
- `offF`/`offT` 파라미터는 **latent no-op**(사실상 미사용 죽은 파라미터). 고치면 PPTX Fig2 출력이 바뀌므로 **의도적 지연**(S4a, §7).

**검증:** 신규 테스트 11건(`review-engine/__tests__/patent-device-diagram-straighten.test.js`) — 밴드 판정 h/v/null, 직선 축약(밴드 중앙 y=40 검증), 장애물 가드, 곡면 가드, 대각 가드, 소스 어서션. 전체 601건 통과.

## 5. 워크플로우 규약 (이 프로젝트에서 확립된 방식)

1. **작업 단위:** 사용자가 태스크마다 브랜치명을 지정(브랜치 가드). 관례: 진단 = `review-engine/diag-<주제>`, 구현 = `review-engine/fix-<주제>`. (마지막 PR #224만 예외적으로 세션 지정 브랜치 `claude/friendly-ptolemy-oag07n` 사용 — 컨테이너 리셋 여파.)
2. **진단 태스크** = READ-ONLY: 코드 수정 0, `docs/review-engine/DIAG-*.md` 작성, push만, **PR 없음**. (다수의 과거 DIAG 문서는 머지 안 된 `review-engine/diag-*` 원격 브랜치에만 존재 — 필요 시 해당 브랜치 fetch)
3. **구현 태스크** = 코드 + 테스트(신규 + 회귀) + 캐시버스트 범프(§4.2) + 전체 테스트 그린 확인 + 커밋 + push + **PR 생성**.
4. **머지는 항상 사용자가** ("머지" 한마디로 확인) → main 푸시 = GitHub Pages 즉시 배포. CI(ci.yml)가 PR에서 `node --test '**/*.test.js'` 실행.
5. PR 본문: 요약 / 변경 내용 / **교차검증(다른 섹션 영향 점검)** / 테스트 결과. 커밋·PR에 모델 ID 미기재.

## 6. 환경·인프라 주의사항 (이번 세션의 사건 기반)

### 6.1 ★ 컨테이너 리셋 = 미push 작업 전멸
실제 발생: 미push 커밋 + 로컬 브랜치 + scratchpad(패치 파일 포함) 전부 소실, 재클론됨, **세션 지정 브랜치도 변경됨**.
→ **규약:** 의미 있는 변경은 즉시 커밋 + 즉시 push. scratchpad에 유일본을 두지 말 것. 리셋이 의심되면(`git log`가 예상과 다르면) 낙담 말고 컨텍스트에서 재적용 — 이번에 전량 복구에 성공한 선례 있음.

### 6.2 MCP(GitHub 도구) 특성
- 도구는 `ToolSearch("select:mcp__github__...")`로 로드 후 사용. 세션 중 연결이 자주 끊김.
- 컨테이너 리셋 직후엔 **그 턴 내내 `invalid session`** 이 지속될 수 있음 → 그 턴에는 복구 불가. PR 생성이 막히면 사용자에게 원클릭 URL 제공: `https://github.com/jaeillroh-create/patent-auto/pull/new/<branch>`

### 6.3 git push 403 재발 시
1. 지수 백오프 4회(2/4/8/16s) — 그래도 403이면 **권한 문제**(네트워크 아님).
2. `mcp__github__get_me`로 신원 확인. `admin-synergyn`(운영) ↔ repo 소유 `jaeillroh-create`(개인) 이중 계정 구조임을 상기.
3. 우회 금지 — 사용자에게 보고. (해결 선례: 사용자가 권한 부여 후 정상화. 임시 대안: `git format-patch` 파일 전달 → 사용자가 로컬 `git am`+push)
4. 비파괴 write 프로브: `git push --dry-run origin HEAD:refs/heads/__perm_probe_delete_me__` (아무것도 만들지 않고 권한만 검사).
