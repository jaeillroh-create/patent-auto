# 디자인 토큰 매핑 가이드 — 시안 → patent-auto

> **목적**: 지원매치 리디자인 시안(React 프로토타입)의 디자인 토큰을, 기존 `patent-auto` 레포의 토큰 체계(`--dt-*`)에 **정확히 매핑**하기 위한 단일 기준 문서.
>
> **원칙**: 시안 색을 새로 도입하지 않는다. 기존 `--dt-*`(Toss DS 클론)가 단일 진실(source of truth)이며, 시안은 여기에 **재색칠(re-map)** 한다. 시안에만 있는 신규 토큰만 `--dt-` 접두사로 추가한다.

---

## 0. 기존 토큰 아키텍처 (건드리지 말 것)

```
Layer 1 · Primitive   shared/design-tokens.css   --dt-*          ← 단일 진실
Layer 2 · Semantic     shared/common.css          --color-*       ← --dt-* 참조 브릿지
Layer 3 · Wanted DS    shared/wanted/tokens.css   --color-blue-*  ← 별도 overlay 표면 전용
```

- 컴포넌트는 **`--dt-*` 또는 `--color-*`(semantic)만 참조**. hex 하드코딩 금지.
- Wanted DS(`--color-blue-*` 등)는 별도 표면 전용 — 메인 앱 리디자인에서는 사용하지 않는다.

> ⚠ **현실 경고**: 위 원칙은 `shared/*`에서만 지켜지고 있다. 기능 모듈(`patent`/`trademark`/`opinion`/`division`)은 이를 무시하고 각자 토큰을 재정의 중. §0.5 참조.

### 🔴 핵심 결함 — 브랜드 블루 3종 분기

| 출처 | 브랜드 블루 | 회색 램프 |
|---|---|---|
| `design-tokens.css` (공식 단일 진실) | `--dt-brand: #1B64DA` | Toss gray |
| `patent.css --pt-primary` · `trademark.css --tm-primary` | **`#3182f6`** (제3의 블루) | Tailwind 라이트그레이 + Toss 다크그레이 혼합 |
| `wanted/tokens.css` | `#0066FF` | coolNeutral |

- `--pt-*` / `--tm-*`는 `--dt-*`를 **무시하고 재정의**한 평행 토큰 시스템. `--pt-primary`/`--tm-primary` = `#3182f6`로 공식 `#1B64DA`와 불일치.
- `--pt-gray-*`/`--tm-gray-*`의 다크 단계(500~800)는 Toss와 일치하나, 라이트 단계(`#f9fafb`·`#f3f4f6`·`#e5e7eb`·`#d1d5db`·`#9ca3af`)는 **Tailwind 회색** — Toss 램프와 미세 불일치.
- `trademark.css`는 `var(--color-x, #fallback)` 패턴으로 Tailwind hex를 fallback에 다수 박아둠.

### 통합 계획 (consolidation) — 리디자인보다 선행

1. **`--pt-*` / `--tm-*` 네임스페이스 폐지** → `--dt-*` 직접 참조로 치환
   - `--pt-primary`/`--tm-primary` (`#3182f6`) → `--dt-brand`
   - `--pt-gray-N`/`--tm-gray-N` → 대응 `--dt-gN` (다크는 1:1, 라이트는 §1 회색표 기준)
2. **opinion/division의 raw hex 치환** → `--dt-*` / `--color-*`(semantic)
3. **`var(--x, #hex)` fallback의 hex 제거** (semantic이 항상 로드되므로 fallback 불필요)
4. **`#C62828`**(components.css danger hover) → `--dt-danger` 계열 토큰화
5. 모듈별로 PR 분리 (`fix/tokens-patent`, `fix/tokens-trademark` ...) — trademark이 가장 큼(424건), 단독 PR 권장

> 이 통합이 끝나야 `--dt-*`가 진짜 단일 진실이 되고, 그 위에 시안 리디자인을 얹을 수 있다. 통합 없이 리디자인하면 4번째 토큰 시스템이 추가될 뿐이다.

### 2.1 타입 스케일 — 시안과 기존 차이 ⚠

기존 `--dt-*`는 **컴팩트(Toss)** 스케일이라 시안보다 작다. 시안의 큰 히어로 타이포는 그대로 옮기면 안 됨:

| 기존 토큰 | 값 | 용도 |
|---|---|---|
| `--dt-f-3xl` | 28px | 히어로 숫자 |
| `--dt-f-2xl` | 22px | 페이지 H1 |
| `--dt-f-xl` | 17px | 섹션 제목 |
| `--dt-f-lg` | 15px | 카드 서브제목 |
| `--dt-f-md` | 13.5px | Nav·본문·Input |
| `--dt-f-sm` | 12px | 라벨·캡션·뱃지 |
| `--dt-f-xs` | 11px | 보조 |
| `--dt-f-micro` | 10px | 뱃지 카운트 |

> **✅ 결정됨 (2026-06)**: 시안의 56~72px 히어로 타이포는 **도입하지 않는다**. 기존 `--dt-f-3xl`(28px)을 상한으로 맞춘다. → `--dt-f-hero` 신규 토큰 추가 안 함. 광고 랜딩·메인의 대형 헤드라인도 28px 스케일로 재조정 (기능명세 도메인1 헤드라인 28자 권고와 정합). 최대폭도 `--dt-max-w`(1120) 단일 — 시안 1200px 폐기.

## 3. 시안에만 있는 신규 토큰 (design-tokens.css에 추가)

아래는 기존에 없으나 리디자인 시안이 요구하는 토큰. `--dt-` 접두사로 `design-tokens.css`에 추가:

```css
/* ── 신규: 매칭 등급색 (S/A/B/C/D) — 지원사업 카드 ── */
--dt-grade-s: #6D28D9;  --dt-grade-s-bg: rgba(124,58,237,0.10);
--dt-grade-a: var(--dt-success);
--dt-grade-b: var(--dt-brand);
--dt-grade-c: var(--dt-warning);
--dt-grade-d: var(--dt-g400);

/* ── 신규: 브랜드 확장 ── */
--dt-brand-deep: #0F3A8C;   /* 그라데이션 끝점 (Toss 블루 계열로 조정) */
--dt-brand-accent: #5B8DEF; /* 다크 배경 위 강조 */

/* ── 신규: 라운드 8 (시안 다용) ── */
--dt-r-sm2: 8px;
```

> 등급색은 기존 semantic(success/brand/warning)을 최대한 재사용하고, S등급(보라)만 신규. 시안의 보라 그라데이션은 Toss 팔레트에 없으므로 **단색 `--dt-grade-s`로 절제**(슬롭 방지).

## 4. 적용 순서 (Claude Code 작업 지시)

1. **`design-tokens.css`에 §3 신규 토큰만 추가** (기존 `--dt-*` 값은 절대 변경 금지)
2. 리디자인 대상 화면의 시안 마크업을 가져올 때, 위 §1·§2 매핑표대로 **시안 토큰명을 기존 `--dt-*` / `--color-*`로 치환**
3. hex 하드코딩(`#3B82F6` 등)이 시안 코드에 남아있으면 **반드시 토큰 변수로 치환** (CLAUDE.md §5 CSS 규칙)
4. 최대폭은 `--dt-max-w`(1120)로 통일 — 시안의 1200px 사용 금지
5. 타입 스케일은 §2.1 기존 스케일 우선. 히어로 대형 타이포는 §2.1 결정사항 확정 후 적용
6. 폰트는 `--dt-font` 단일 — 시안 Wanted Sans display 도입 금지

## 5. 절대 하지 말 것 (token drift 방지)

- ❌ `--dt-brand` 값을 `#3B82F6`로 덮어쓰기 (브랜드 블루 변경)
- ❌ 시안 회색(slate)을 `--dt-g*`에 덮어쓰기
- ❌ 새 `--color-*` semantic을 `--dt-*` 없이 직접 hex로 정의
- ❌ Wanted DS(`--color-blue-*`)를 메인 앱 화면에 끌어쓰기
- ❌ 컴포넌트 CSS에 hex 직접 작성
